# Заявки сайта в Telegram

Подготовлен обработчик `/leads` для существующего Worker `tochka-telegram-relay`. Развёртывание ещё не выполнено. Токен действующего бота остаётся в Cloudflare Secret `BOT_TOKEN`; его нельзя добавлять в репозиторий или код сайта.

`relay-base.mjs` — неизменённая локальная копия существующего `cloudflare-worker.js` из корня проекта. Перед обновлением Worker сверить её с актуальным кодом в Cloudflare: если там появились новые изменения, сначала обновить базовую копию. `worker.mjs` добавляет обработчик лидов, а прежние маршруты передаёт существующему коду.

## Развёртывание

Из корня репозитория `сайт`, в терминале с сетевым доступом:

```powershell
npx wrangler@4 login
npx wrangler@4 deploy --config backend/wrangler.toml
```

Вход в Cloudflare выполняет владелец аккаунта. Прежде чем подтверждать deploy, убедиться, что выбран тот же аккаунт и Worker `tochka-telegram-relay`. `keep_vars = true` сохраняет существующие обычные переменные; существующие секреты Cloudflare не включаются в исходники.

В Cloudflare → Worker → Settings → Variables and Secrets добавить `LEADS_CHAT_ID` — ID подтверждённого получателя заявок. Для личной доставки пользователю из текущей конфигурации проекта кандидат — `524756735`; выбор получателя должен быть подтверждён владельцем. Для группы нужен её ID и добавление бота в группу. Для личной доставки получатель должен предварительно запустить бота.

Сохранить действующие BOT_TOKEN, WEBHOOK_SECRET, RELAY_SECRET и YANDEX_FUNCTION_URL. Wrangler создаёт привязку `LEADS_RATE_LIMITER`: 3 попытки в минуту на ключ IP в пределах локации Cloudflare. Это базовое ограничение, не CAPTCHA и не гарантия глобального предела.

Проверить:

1. `https://tochka-telegram-relay.killreal2227.workers.dev/health` — прежний мост работает.
2. `https://tochka-telegram-relay.killreal2227.workers.dev/leads/health` — `ready: true`.
3. Только затем в `site/lead-form.js` заменить `endpoint:null` на `endpoint:'https://tochka-telegram-relay.killreal2227.workers.dev/leads'`, выполнить проверки и опубликовать сайт.
4. Отправить согласованную тестовую заявку через сайт, проверить фактическое сообщение у получателя. До этого не считать доставку проверенной.

## Поведение

Сервер проверяет Origin, размер, имя, телефон, филиал, направление, версию и факт согласия, ссылки на документы и скрытое поле. Получателя и токен посетитель не задаёт. Ответ `ok: true` возвращается только после положительного ответа Telegram с message_id.

Не выполняются фоновые повторы отправки. При сетевой неопределённости заявка могла дойти: посетителю предлагается уточнить запись по телефону. Exactly-once доставка не заявляется; при повторной ручной отправке возможен дубль, номер заявки включён в сообщение. Для полноценной очереди и постоянной дедупликации потребуется отдельное хранилище.

Тело заявки и IP не журналируются кодом обработчика. Telegram-сообщение содержит имя, телефон, филиал, направление и сведения о согласии. Данные проходят через Cloudflare и Telegram, поэтому политика сайта должна соответствовать этому потоку. Юридическая проверка фактической обработки отдельно не выполнена.
