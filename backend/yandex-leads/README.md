# Заявки сайта: Yandex → AlfaCRM → уведомления

Цепочка: SmartCaptcha → подтверждённое сохранение YDB → FIFO → AlfaCRM.
Telegram получает филиал, направление, идентификатор и результат, без имени и телефона.

## Поведение

- Калуга — branch 7, Троицк — 53; источник 3; новый этап 37 «Заявка с tzvuka.ru», воронка 1.
- Создание подтверждается чтением карточки: телефон, метка, филиал, источник и этап.
- До создания — поиск телефона среди лидов и учеников, включая архив. Существующая карточка не меняет статус/источник/ответственного. Повторное обращение остаётся в YDB; менеджеру приходит предупреждение со ссылкой, требующее разбора.
- При сбое CRM Telegram сообщает о неподтверждённой передаче. После подтверждения редактируется то же сообщение. Ошибка Telegram не вызывает нового создания подтверждённой карточки.
- Одна FIFO-группа сериализует обращения к аккаунту. Получается один элемент; пауза клиента от 2,2 секунды между API-запросами. Visibility 300 секунд превышает предел функции 60 секунд. Минутный таймер выбирает одну доступную заявку; новые заявки тоже обрабатывают очередь.
- Токен кешируется. После ошибки/429 текущая обработка прекращается: цикла сетевых повторов нет.
- До create сохраняется creating. После потери ответа — сверка по телефону и метке. Неоднозначный результат требует ручного разбора, без повторного создания вслепую.

## Формат и хранение

Сервер совместим с v1/v2. Новый клиент отправляет v2 и версию уведомления 2026-11-16-v3, без фиктивного consent.accepted. Фамилия необязательна. Метаданные фиксируют инициативную заявку на занятие, не рекламное согласие.
Добавлены nullable-поля существующей таблицы; TTL в этой задаче не включался, старые записи и сообщения не удалялись.
Служебные ключи sent:, crm:, notice:, deleted: не являются заявками. Экспорт исключает их; средства удаления учитывают связанные маркеры. Удаление требует отдельного подтверждения.

## Ограничения и действия администратора

- existing_review и attention требуют разбора менеджером; автоматического изменения существующего клиента нет.
- Если YDB сохранила заявку, но очередь не подтвердила SendMessage, Telegram предупреждает. Повторная постановка — IAM-приватный вызов с crmReceipt. Межсервисной транзакции YDB/очереди нет.
- Ручное удаление Telegram-сообщения может потребовать восстановления уведомления. Дубликаты уведомлений при потере ответа возможны; exactly-once для двух внешних сервисов не обещается.
- FIFO хранит сообщение с receipt 14 суток. Это не срок хранения заявки. Длительные pending/предупреждения нужно разбирать.
- При одновременном отказе хранилища и уведомлений нельзя гарантировать внешнее сообщение. saved=true выдаётся только после подтверждения YDB.

Секреты — в Lockbox, в коде/ZIP их нет. crm_smoke.py исключён из production ZIP и не подключается к Gateway. Результаты облачных проверок: release/CRM-CLOUD-VERIFIED.json.
