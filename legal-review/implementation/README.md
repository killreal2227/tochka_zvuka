# Офлайн-заготовка перехода v1/v2

Не подключена к production; не выполняет HTTP-запросы, сохранение или миграции. Использует действующий service.py только для прежней валидации/общих ограничений. Подмена глобального valid, monkey-patch рабочего процесса и фабрикация consent не применяются.

Из корня репозитория: `python -m unittest discover -s legal-review/implementation -p test_contract_v2_candidate.py -v`.

Результат 14.11.2026: **13 тестов, OK**, только синтетические данные и stdlib. Проверены сохранение receipt v1, v2 без фиктивного согласия, необязательная фамилия, строгие поля/версия уведомления, границы времени, филиалы, стабильность ключа и независимость серверных метаданных. Совместимость YDB/сохранения и реальная CAPTCHA/Telegram этим не доказаны.

Вызов prepare допустим только после проверки Origin/контекста/лимитов, серверной CAPTCHA и утверждения реального основания цели. Полученный объект — данные для будущего адаптера, не подтверждение сохранения. Подробнее: [14](../14-form-v2-implementation.md).

Новый сервер сначала поддерживает обе версии и согласованное хранение. Только затем меняется клиент и снимается required у фамилии. Старые pending не перекодируются. Перед выпуском проверить ошибки хранения/повторы и реальную запись/чтение на разрешённой синтетике.
